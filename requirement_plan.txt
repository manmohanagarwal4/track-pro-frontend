# Flutter GPS Tracker App — Frontend-Only Production-Quality Prototype

## ROLE

You are a senior Flutter developer, mobile UX/UI designer, Flutter architect, and IoT/GPS tracking application specialist.

Build a **fully functional, polished Flutter mobile application for a GPS tracking platform**.

This is the **frontend/mobile application phase only**.

### CRITICAL REQUIREMENT

**DO NOT integrate any backend API, REST API, WebSocket, MQTT, Firebase backend, database server, or external GPS tracking service.**

For this phase, **everything must work using local dummy/mock data**.

The application should look and behave like a real production GPS tracking application, even though all data is simulated locally.

I will create a separate backend/API development prompt later.

# 3. IMPORTANT ARCHITECTURE

Even though there is no backend yet, structure the code so the dummy implementation can later be replaced by real APIs without rewriting the UI.

Use:

```text
UI
 ↓
State Management
 ↓
Repository Interface
 ↓
Mock Repository
 ↓
Local Dummy Data
```

For example:

```dart
abstract class TrackingRepository {
  Future<List<TrackerDevice>> getDevices();

  Future<TrackerDevice?> getDevice(String id);

  Future<List<DeviceLocation>> getLocationHistory(
    String deviceId,
    DateTime start,
    DateTime end,
  );
}
```

Then:

```dart
class MockTrackingRepository implements TrackingRepository {
   ...
}
```

The UI must only depend on the repository interface.

Later I should be able to create:

```dart
ApiTrackingRepository
```

without changing the UI.
